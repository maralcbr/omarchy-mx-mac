# Omarchy MX Mac 4.0.4-mac.1

Based on upstream Omarchy v4.0.4. This is the first MX Mac release since
4.0.2-mac.1 to be published here, so it also covers the Mac work that shipped
through the signed channels in between.

## Install

- **New Mac:** download the
  [Omarchy MX Mac Installer](https://downloads.aicodelabs.com.au/installer/stable/Omarchy-MX-Mac-Installer.pkg)
  (2.0.9, signed and notarized). It opens on Stable. Both installer channels
  write signed image `os-v4.0.3-mac.5.20260923-rc`, which carries this 4.0.4
  runtime; the `4.0.3` in the image tag is a naming slip in the signed catalog.
  The image admits the MacBook Pro 14" M1 Pro (`apple,j314s`) and 16" M2 Max
  (`apple,j416c`).
- **Existing Mac:** run `omarchy update`.

## Changes

- **Upstream 4.0.4.** Imports upstream's x86 kernel changes (`linux-omarchy`,
  matching headers, the retired Panther Lake kernel swap). Both new kernel
  migrations are skipped on Apple Silicon, which keeps its own kernel and boot
  setup.
- **Aurora kernel on new installs.** Fresh installs on both channels get
  `linux-aurora` from `aurora-silicon/linux`: several external displays over
  USB4 and DisplayPort alt-mode, variable refresh rate, the camera and the
  always-on processor. Three Aurora lanes exist (stable, rc, edge); Macs
  installed from the earlier Asahi image keep `linux-asahi`.
- **Limine boot menu.** New installs boot U-Boot → Limine with unified kernel
  images and snapper snapshots in the menu. U-Boot is silent.
- **Installer 2.0.9.** Opens on Stable at every launch; the Release Channel menu
  offers Stable and RC. The payload downloads while you choose a disk size, and
  keeps downloading when you change it. Disk shortfalls are reported with
  numbers before anything is downloaded.
- **Encryption.** Optional LUKS2 root, converted on the first boot, with a
  per-machine re-key, recovery key and drive password.
- **Snapshots.** Snapper takes update snapshots; GRUB snapshot restores remain gated.
- **Updates.** The boot check recognises `sd-encrypt` in a systemd initramfs,
  the update admission check treats `omarchy-mac-boot` as the owner of the Apple
  boot files, and the shipped Omarchy keyring is populated before updates are
  refused.

## Validation

- Package candidate `2949b88c`: native ARM64 VM
  installation, recovery and reboot, with all 23 optional application
  installs passing.
- Image `os-v4.0.3-mac.5.20260923-rc` (runtime channel 56): first-boot VM
  acceptance passed all seven checks: image signature and provenance, payload
  unpacking, member digests, a generic kernel plus an initramfs built with the
  image's hooks, a plain first boot, an encrypted first boot (LUKS2
  conversion), and a second boot unlocked through `sd-encrypt`. The VM does
  not boot the Aurora kernel or the Apple boot chain.
- Package hardware evidence for `2949b88c` records the silent U-Boot and
  successful reboots on a reference Mac.
- Source test suites pass in CI on `main` (`3bad71cb`).
- A physical fresh install of this image has not been recorded yet; the first
  ones are on the M1 Pro and M2 Max reference Macs.
